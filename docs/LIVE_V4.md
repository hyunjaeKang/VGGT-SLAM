# Live V4 — 지도 생성 중 사전 객체 검색

계획: `26.11.09.VGGT_SLAM.Plan.html`. V1~V3 및 기존 run을 보존하고 V4 컨트롤러·뷰어·시맨틱 워커를 별도로 추가했다.

## 실행

```sh
.venv/bin/python demo.py live4 --port 8105 --viewer-port 8106
```

http://localhost:8105 에서 디스크 영상을 선택하고 사전 대상(기본 car,person,bicycle)을 입력한다. YOLO26/YOLO11은 학습된 클래스만 지원하며 printer 같은 자유 명칭은 YOLOE 또는 생성 후 정밀 검색을 사용한다. 첫 실행은 VGGT 로딩 때문에 지연된다. 실행 기록은 `logs/demo_v4_runs/`, 실제 지도는 `logs/demo_runs/`에 저장된다. V1~V3의 주소와 구현은 유지한다.

## 구현

- R0: 컨트롤러 단계 시간, 워커 추론·깊이 결합 시간, 모델 해시와 로딩 횟수를 실행별 JSON/JSONL로 저장한다.
- R1: 상주 객체 모델과 별도 도로·하늘 모델. 실시간 소스는 최신 프레임 한 칸만 유지하며 오래된 프레임을 버린다. 지도에 확정된 프레임은 별도 처리하고 같은 이미지 해시의 추론은 디스크 캐시로 재사용한다.
- R2: 기본 YOLO26n-seg CPU, 선택 YOLO11n-seg/YOLOE26s/SAM3. SAM3 경로는 기존 open-set 환경을 사용하고 도로 모델을 함께 실행하지 않는다.
- R3: ByteTrack의 2D ID, run·프레임·이미지 해시 기반 UID, SQLite WAL 관측 저장. 깊이와 정확한 프레임을 결합하고 로컬 점 지지를 저장한 뒤 최신 그래프 변환으로 재투영한다. 동적 후보의 3D 박스는 해당 프레임에만 표시한다.
- R4: SegFormer B0 Cityscapes 도로·하늘 분할. 도로는 체적 객체 박스를 만들지 않고 도로 표면/BEV 연결 레이어로 표시한다. 생성 중 하늘 필터와 점진적 지도 캐시 갱신을 지원한다. V2의 재생·뷰 조절 기능을 V4 뷰어에 유지한다.
- 생성 중 사전 클래스 검색은 저장된 관측을 즉시 조회한다. 임의 텍스트 정밀 검색은 지도 생성 후 제공한다.

## 검증 증거

`evidence/browser_live_v4_20261109_02/`: 실제 6프레임 영상 업로드→지도→도로→검색 완료, 모델 로딩 1회, 중복 이미지 추론 재사용, 브라우저 JS 예외 0. 총 약82.45초. 첫 지도 약45초. 이후 동시 2D 처리와 점진적 캐시 갱신을 보완했으므로 최신 재검증은 다음 번호의 evidence를 확인한다.

`evidence/v4_r0_models_20261109_01/`: 단일 PandaSet 프레임 모델 비교. 초기 비교 YOLO26 CPU 약35~39ms, MPS 약101~148ms. 이 수치는 SLAM 전체 처리율이 아니다. CoreML 변환 성공, warm 약73~78ms, 검출14개. 마스크 정확도 동등성 검증 전이므로 기본으로 채택하지 않았다. SAM3 모델 로딩1회·호출2회에서 마스크 해시가 같았지만 프레임당 약30초였다.

`tests/test_live4_semantics.py`: UID, 음성 관측, 멱등 저장, 동시 쓰기, 프로젝트 변환, 동적 잔상 방지, 캐시 점진 갱신 및 기존 버전 분리를 검증한다.

## 한계와 다음 수용 기준

계획의 10Hz/p95 350ms, 지도 확정 후500ms, 3D 데이터 나이5초는 목표이며 달성 보장이 아니다. VGGT/MPS와 CPU 자원 경쟁이 존재한다. 전역 객체 ID는 아직 None(미확정)이며 2D 추적 ID를 전역 ID로 간주하지 않는다. 도로 모델은 Cityscapes 도메인이므로 별도 GT 정확도 평가가 필요하다. R5의 30초·90초 전체 수용 시험/GT 평가 및 R6의 조건부 CUDA·다른 기하 엔진 교체는 완료로 표시하지 않는다.

## 환경 및 재현

`.venv-v4`는 기존 `.venv`의 Torch2.3.1 등 기반 패키지를 읽는 로컬 `.pth` 브리지 환경이다. 독립 배포용 환경은 아니다. V3 환경은 업그레이드하지 않았다. 추가 패키지 버전은 `docs/research/v4_environment.txt`, 모델은 `logs/demo_models/v4/`와 `docs/research/v4_model_hashes.txt`을 참조한다. Ultralytics와 각 모델의 라이선스는 배포 전에 해당 공식 라이선스를 확인해야 한다. 임의 모델 다운로드는 실행 중 수행하지 않고 로컬 파일을 사용한다.

기본 모델 준비(새 환경에서 네트워크 필요): `.venv-v4/bin/python scripts/demo_prepare_models_v4.py`. YOLOE는 Ultralytics 공식 yoloe-26s-seg 체크포인트와 MobileCLIP 텍스트 인코더가 추가로 필요하다. CoreML 패키지는 선택 비교용이며 현재 UI 기본 백엔드가 아니다. 로컬 브리지를 다른 경로로 옮기면 `.pth` 절대 경로를 다시 지정해야 한다.

실행별 지연 요약: `.venv/bin/python scripts/demo_report_live4.py logs/demo_v4_runs/<job-id>`.

최신 동시 처리 경로 `evidence/browser_live_v4_20261109_04/`: 지도6/도로6/의미6, 객체 모델 로딩1회 완료. 이번 실행은 약266초로 이전보다 느렸으며 모델 지연 목표를 충족하지 못했다. 상세 p50/p95는 `timing_summary.json` 참조. 별도 스레드가 처리 독립성은 제공하지만 이 Mac에서 속도 향상은 아직 입증되지 않았다.

재검증04는 생성 완료 후 브라우저 검색 확인 중 CDP timeout으로 끝났으므로 전체 PASS가 아니다. 로그에서 발견한 증분 프레임 선택/시간표 갱신 순서 오류를 수정했고, 서브맵 중복 프레임을 V4에서 제거했다. 추가 회귀 포함 의미/캐시 테스트15개 PASS. 완료 지도를 수정된 뷰어로 다시 열었다. 전체163개 PASS 결과는 이 마지막 두 수정 이전이며 이를 구분한다.

정정: 서브맵 겹침은 query playback_index와 일치하도록 보존해야 한다. 중복 제거 시 도로 관측 인덱스가 어긋남을 재열기 검사에서 발견해 제거 변경을 되돌렸고, 인덱스 보존 회귀 테스트로 대체했다. 소스 고유6프레임/뷰어7개 서브맵 관측이다. 시간표 갱신 순서 수정은 유지한다.
