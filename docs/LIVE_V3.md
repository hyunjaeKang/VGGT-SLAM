# Live V3 — 비디오에서 새 지도 생성

실행 중인 화면: <http://localhost:8103>. 버전 선택은 <http://localhost:8100>.

```bash
.venv/bin/python demo.py live --port 8103 --viewer-port 8104
```

1. **디스크에서 영상 선택**으로 MP4/MOV/MKV/AVI/WebM/M4V를 선택한다. 원본을 수정하지 않고 별도 작업 폴더에 업로드한다(최대 4 GiB).
2. 필요하면 처리 설정을 연다. 기본은 서브맵 8, 최대 입력 프레임 0(전체), 키프레임 이동 기준 10, 최대 루프 1이다. 짧은 검증은 서브맵 3 / 최대 프레임 6 / 이동 기준 0 / 루프 0을 사용했다.
3. **지도 생성 시작**을 누른다. 실제 `main_realtime.py`가 VGGT 깊이·카메라·점군·서브맵 연결과 그래프 최적화를 수행한다. 첫 완성된 서브맵부터 V2 기반 3D/RGB/BEV 뷰가 나타나고 이후 완성된 결과를 추가한다.
4. SAM3가 `road`를 별도 계산한다. 처리된 프레임의 도로 표면과 BEV 연결 지도를 순차 반영한다. 더 최신 서브맵이 생기면 최신 스냅샷의 전체 고유 키프레임을 처리하며 앞서 얻은 마스크는 공유 캐시로 재사용한다. 도로 표시는 관측 표면의 인접 셀 연결이며 주행 가능성 판정은 아니다.
5. 완료하면 하늘 필터와 원본 재생용 MP4를 준비하고 최종 run으로 전환한다. **검색 · Search → Query → Search**로 전체 구간의 고유 키프레임을 검색한다. V2의 마스크·박스, 결과 프레임 이동, 저장 검색 삭제, 뷰 크기·패널·BEV 조작을 사용할 수 있다.
6. **이전 V3 지도 → 열기**로 완료된 작업을 다시 연다. 서비스 재시작 후에도 작업 기록을 읽는다. **생성 중지**는 V3가 시작한 자식 작업만 중단하고 이미 저장된 입력·결과·로그를 보존한다. 중단된 작업을 이어서 추론하는 기능은 없다. 새 생성은 항상 새 run이다.

## 실시간 표시의 의미

계산이 끝나는 대로 서브맵 단위로 반영하는 점진 처리이다. 매 영상 프레임에서 30/60fps로 새 깊이·도로를 계산한다는 의미는 아니다. 생성 중 새 결과가 도착하면 최신 지도 프레임으로 이동한다. 이때 검색은 비활성화하고 생성 완료 후 활성화한다. 마지막 전환에서 작업 뷰를 한 번 다시 연결한다. 이후 V2의 독립 RGB 영상 재생·카메라 보간을 사용한다.

상단 `지도` 숫자는 중복을 제외한 고유 키프레임 수이다. 뷰어 타임라인에는 서브맵 간 중첩 관측도 들어가므로 타임라인 프레임 수가 더 클 수 있다. ROAD 검색은 고유 키프레임 전체를 검사하며 영상의 선택되지 않은 중간 프레임까지 분할하지 않는다. `최대 입력 프레임`은 디코딩 범위를 제한하며 키프레임 수를 지정하는 값이 아니다. 입력 FPS는 ffprobe로 읽고 기록된 영상 타임스탬프와 함께 사용한다.

계산 시간은 영상 길이·해상도·움직임·장치에 따라 달라진다. 이 Mac의 VGGT는 MPS, SAM3는 별도 현대 Torch 환경에서 CPU를 사용한다. 긴 영상은 도로 분할과 전구간 검색이 특히 오래 걸릴 수 있다. 모델·깊이·지도는 실제 계산하며 다른 run의 결과를 대신 보여주지 않는다. 3D의 스케일과 기하 정확도는 기존 VGGT-SLAM의 상대 복원 조건을 따른다.

## 저장 구조와 보존

- `logs/demo_v3_jobs/<unique>/`: 업로드한 복사본, `job.json`, 실행 명령, 추론/도로/뷰어/하늘/미디어 로그, 완료 스냅샷만 포함하는 표시용 `live_run`, 갱신 신호 `live_control.json`.
- `logs/demo_runs/video_<unique>/`: 실제 Recorder가 작성하는 원본 이벤트·RGB·깊이·최적화 스냅샷·`poses.txt`·`poses_points.pcd`.
- 실제 run의 `evidence/v3_snapshots/<step>/`: 완료된 최적화까지의 불변 이벤트 접두부와 완료 자산 링크. ROAD worker가 기록 중인 JSONL/NPZ를 읽지 않는다.
- `evidence/segmentation_cache_v3/`: 같은 run 내 ROAD 단계 간 재사용. 최종 검색 결과는 기존 `evidence/query_jobs` 형식으로 등록한다.
- `evidence/sky_v3/`, `evidence/smooth_media_v3/`: 원본 3D 자산을 덮어쓰지 않는 표시용 캐시.

V1(8101)·V2(8102)는 별도 프로세스로 유지한다. V3의 제어 서버(8103)와 작업 뷰(8104) 포트는 서로 달라야 하고 비어 있어야 한다. 서버는 로컬 루프백에만 바인딩한다.

## 검증 명령

```bash
.venv/bin/python -m pytest -q
.venv/bin/python scripts/demo_browser_live.py \
  --video logs/demo_fixtures/pandaset33_1fps_20261105/clip.mp4 \
  --frames 6 --output evidence/browser_live_v3_<unique>
```

브라우저 검증은 Chrome의 실제 파일 입력 선택, 실제 MPS 추론, 도로 분할, 생성 중 검색 비활성화, 완료 후 전체 구간 `car` 검색을 실행한다. mock 모델이 아니다. 작은 실험의 상세 결과와 제한은 `DEMO_PROGRESS.md`에 기록한다.

## 2026-11-08 후속 수정과 현재 작업

- 영상 선택 버튼은 실제 파일 창을 열도록 변경했다. 생성 중에도 다음 영상 선택은 가능하며, 새 생성 시작은 완료/중지 후 가능하다. 파일 선택 자체가 현재 작업을 중단하지 않는다. 파일 창 취소 시 앞서 선택한 파일을 유지하고 같은 파일도 다시 선택할 수 있다. 기존 탭은 새로고침한다.
- MOV의 Display Matrix90/180/270도를 추론 전에 적용한다. 사용자 `duke_status.mov`는180도 회전 정보가 있어 기존 RGB·지도 모두 뒤집혔다. 수정 이후 새 생성은 정상 방향이며 기존 반전 입력의 지도 전체는 재생성이 필요하다. 원본/과거 결과는 그대로 보존한다.
- 자유3D Fit map의 위쪽 방향은 기록 카메라 기준이다. RGB Reset으로 해당 프레임 카메라에 복귀한다.
- 최신 소량 검증은149개 회귀와 실제 MOV6프레임 재추론이다. **6프레임 실험을 전체 영상 실시간 처리 증거로 쓰지 않는다.**
- 현재 사용자가 별도로 실행한90초 작업은 `live_20261108T115826_4ffce9d7` / `video_20261108T195829_755817000`. 완료 여부는 job.json과 저장 파일을 다시 확인한다.
- 생성 중 미리 정한 일반 객체까지 찾는 V4는 아직 설계 단계다. [계획서](../26.11.09.VGGT_SLAM.Plan.html), [인계](SESSION_HANDOFF.md), [현황](CURRENT_STATUS.md)을 참고한다.
